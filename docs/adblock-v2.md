# v2：国内 App 广告仍出现时如何检查

2026-10-18 修订。旧版只有域名过滤和 5 条窄范围 URL Rewrite，未包含微博/知乎的信息流响应处理。重新编译主配置或清理后台不能增加这些能力；HTTPS 解密未生效时，旧版的 HTTPS 路径规则也不会生效。

## 本次覆盖

| App/层级 | v2 的处理 | 必要条件 |
| --- | --- | --- |
| 通用广告/追踪域名 | anti-AD、AdvertisingLite 的域名规则，去重并扣除白名单 | 模块启用、当前全局路由为“配置” |
| 知乎 | 已知开屏/广告请求；推荐、部分回答信息流中 `feed_advert` / `market_card` / `ad` 等明确标记 | MITM 生效、`Zhihu-AdFeed` 脚本下载成功 |
| 微博 | 广告预加载/实时开屏请求；已列明的信息流、卡片、评论集合中的明确广告标记 | MITM 生效、`Weibo-AdFeed` 脚本下载成功 |

脚本由本仓库维护，在设备本地处理响应，不发起额外请求、不保存账号数据。仅删除带明确广告标记的集合条目，保留普通文本、视频、分页游标和 64 位 ID；错误/新结构无法识别时保留原响应。脚本仅运行在模块列出的精确主机与接口。未承诺清除这两个 App 所有广告，其他国内 App 的同源信息流也不因此自动覆盖。

## 手机端一次性操作

1. Shadowrocket → 配置 → 模块 → 更新 `Independent-AdBlock`。必要时删除旧模块后，重新导入下面地址；**只更新主配置不会替你更新旧模块内容**。

   https://raw.githubusercontent.com/vowm3440/shadowrocket-rules/main/adblock.sgmodule

2. 打开模块查看描述，应显示 **`v2 知乎/微博广告过滤`**；检查有 `Zhihu-AdFeed` / `Weibo-AdFeed` 两条脚本及 `objects/<SHA256>.js` 地址。下载失败时先解决 GitHub Raw 的访问问题，不应继续判断广告效果。
3. 全局路由选择“配置”，启用该模块。在**当前正在使用的配置**中启用 HTTPS 解密，选择设备上已有的有效 CA，或按 README 生成并安装 CA；iOS 的“证书信任设置”也须信任同一证书。单纯安装描述文件并不等于已完全信任。
4. 确认精确解密主机中包含 `api.zhihu.com`、`web-render.zhihu.com`、实际使用的 `api.weibo.cn` / `api.weibo.com` / `mapi.weibo.cn` / `mapi.weibo.com`。不要添加所有网站或银行/支付通配域名。不向仓库上传证书或私钥。
5. 更新模块及外部资源后使用/编译配置，重连一次隧道。暂时停用其他对同一接口的重写/脚本，避免多个模块覆盖响应；随后在 App 中拉取新的推荐内容测试。
6. 如 App 仍展示之前缓存的开屏素材，优先使用 App 自带的清缓存功能，完全退出后重开。不要为排查随意删除 App，以免丢失本地数据。

## 用日志区分原因

| 看到的现象 | 下一步 |
| --- | --- |
| 模块仍无 v2 描述/无两条脚本 | 更新的是旧模块内容，先重新下载模块 |
| 没有对应 HTTPS 解密记录，脚本从未执行 | 核对当前配置、CA 安装/信任、MITM 开关与精确域名；某版本有证书锁定时撤掉该主机 |
| 脚本/规则对象下载失败 | 先恢复资源访问，再编译 |
| 日志 `Independent-AdBlock v2 ... removed N` | 本次响应已删去 N 个标记广告；继续检查剩余广告类型 |
| 日志提示 `response unchanged` | 响应格式不兼容，脚本保留原响应；需要针对版本补充 |
| 脚本命中但未过滤，或广告请求不在现有接口 | 提供 App 名称、版本、开屏/信息流/视频广告类型及相关请求主机/路径 |

分享日志请移除 Cookie、Authorization、手机号、用户 ID 与查询参数中的令牌；只提供广告相关的最小字段示例。银行/支付异常先关闭本模块对比，不扩大解密范围。

当前验证包括 11 组合成响应行为检查、规则回归和输出哈希/引用校验。没有连接用户的 iPhone，**尚未进行 Shadowrocket 实机编译和广告效果验证**。网页/客户端升级、个性化投放、未标记软文与服务端插入视频广告仍需单独处理。
