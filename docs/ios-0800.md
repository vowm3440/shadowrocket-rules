# iOS 每天北京时间 08:00 更新：实操与边界

## 先明确可实现的结果

可以创建每天 08:00 的“特定时间”个人自动化，先检查仓库的实际发布版本，再调用 Shadowrocket 的配置导入和模块安装 URL。**不能承诺锁屏状态下无交互、准点完成两个文件的更新与编译。**GitHub 可能延迟构建；iOS 可能限制跨 App 打开、锁屏执行或导入操作。没有公开且已核实的 Scheme 能为本方案提供完整静默更新与完成回执。

本教程不把 `shadowrocket://update-subs` 当作更新规则，也不声称设置一个后台刷新间隔就能锁定每天 08:00。

## A. 先完成一次手动安装

1. 按 README 部署仓库，手动运行 Actions 至成功。确认生成文件已绑定真实仓库。
2. 添加并使用远程 `routing.conf`，启用“配置”路由模式。
3. 添加远程 `adblock.sgmodule`，启用后编译。记录模块是否已开启；**自动化不得为了更新而擅自重新打开你主动关闭的模块**。
4. 设备上至少有一个工作正常的代理节点，允许快捷指令访问网络和打开 Shadowrocket；第一次所有授权都在解锁时完成。
5. 先不装 MITM 证书，验收域名层；需要精确路径重写时再按 README 设置。

## B. Shadowrocket 内部的每日兜底

菜单可能随版本改变，以实际界面为准：

1. iOS 设置 → 通用 → 后台 App 刷新，开启系统与 Shadowrocket 的允许。
2. Shadowrocket → 设置 → 配置：开启“自动后台更新”和“更新提醒”，更新间隔 **1 天**。
3. Shadowrocket → 设置 → 模块：开启“自动后台更新”和“更新提醒”，更新间隔 **1 天**。
4. “订阅”的后台更新只更新节点；可以按个人需求设置，不能替代上面两项。
5. 不主动从多任务界面杀掉应用；重启后先解锁并手动打开一次。系统省电/网络限制可能进一步影响执行。

这些后台任务用于兜底，没有固定北京时间。远程配置更新一般会覆盖本地配置修改；证书等仅在本机维护的内容请用设备本地证书模块/本地扩展保留，绝不上传私钥到公开仓库。

## C. 建立“SR 获取今天版本”快捷指令

以下步骤使用系统“快捷指令”的普通操作，**不提供未经本机签名验证的 `.shortcut` 文件**。创建一个名为 `SR 获取今天版本` 的快捷指令。先把下面的 `vowm3440/shadowrocket-rules`、`main` 改成实际值。

### C1. 取默认分支的提交 SHA

按顺序添加操作：

1. **当前日期**。
2. **格式化日期** → 自定义格式 `yyyyMMddHHmmss`，保存为变量 `Nonce`。这里仅用作避免复用请求 URL，不承担北京时间校验。
3. **文本**：

```text
https://api.github.com/repos/vowm3440/shadowrocket-rules/commits/main?sr_nonce=Nonce
```

把 `Nonce` 换成第二步的魔法变量，不要保留字面文本。分支名含 `/` 等字符时，应对分支名 URL 编码；建议先使用 `main`。

4. **获取 URL 内容** → GET，在展开项中添加请求头：

```text
Accept: application/vnd.github+json
Cache-Control: no-cache
```

5. **获取词典值** → 键 `sha` → 保存为 `CommitSHA`。API 若返回 `message` 错误而没有 `sha`，通知失败并**停止此快捷指令**。可用“如果 CommitSHA 没有任何值”分支执行此判断；进一步用“匹配文本”校验 `^[0-9a-f]{40}$`。

公开仓库通常无需令牌。GitHub API 未认证访问有速率限制，每天一次正常使用即可；不要在个人自动化中每秒轮询。网络请求失败会直接中断当次快捷指令，旧配置继续保留；完成后从执行记录查看原因。

### C2. 从同一个 SHA 校验 manifest

6. 添加 **文本**，插入 `CommitSHA`：

```text
https://raw.githubusercontent.com/vowm3440/shadowrocket-rules/CommitSHA/manifest.json
```

7. **获取 URL 内容** → GET → **从输入获取词典**（若已经是词典可省略转换）。保存为 `Manifest`。
8. 读取词典键 `requires_repository_binding`。如果为真，通知“规则尚未绑定仓库”，停止。
9. 读取 `generated_at`，用“从输入获取日期”解析，再与当前日期比较。读取 `generated_date_bjt` 作为显示和校验值。
10. 计算**今天北京时间 07:50**这个阈值，要求构建时间不早于它；要求构建时间不晚于当前时刻，以免错误的未来日期通过。

时间设置的实际方法：如果手机日常就在中国时区，把系统时区保持为北京，以当天的 `yyyy-MM-dd 07:50:00 +08:00` 文本转换为日期进行比较。当日期格式操作提供时区选项时，明确选 `Asia/Shanghai`。如果该 iOS 版本不提供格式时区选项，且手机使用其他时区，先按北京时间确定当天日期，或在快捷指令中按当前 UTC 偏移计算；**不要拿美国当地日期直接和 `generated_date_bjt` 比较**。

11. 不满足时间要求：**显示通知**“今天 07:50 的规则尚未发布，保留当前配置”→ **停止此快捷指令**。可另建 08:10 的重试自动化，运行同一快捷指令，不用长期等待循环。

当 Actions 排队时，08:00 拿到昨天 manifest 是正常的失败情形；不能通过改 `?t=` 把尚未发布的构建变出来。SHA 锁定保证一次会话内取到同一提交的文件，不保证 GitHub/网络永远及时反映最新分支提交。

### C3. 生成两个经过版本锁定的导入链接

12. 创建变量 `ConfigURL`：

```text
https://raw.githubusercontent.com/vowm3440/shadowrocket-rules/CommitSHA/routing.conf
```

13. 创建变量 `ModuleURL`：

```text
https://raw.githubusercontent.com/vowm3440/shadowrocket-rules/CommitSHA/adblock.sgmodule
```

14. 将 `ModuleURL` 通过 **URL 编码** 操作编码为一个完整查询参数值，保存为 `EncodedModuleURL`。只编码一次。
15. 用“词典”操作组装并输出以下三个键，供下一节使用：

| 键 | 内容 |
| --- | --- |
| `config_scheme` | `shadowrocket://config/add/` 后拼接完整 `ConfigURL` |
| `module_scheme` | `shadowrocket://install?module=` 后拼接 `EncodedModuleURL` |
| `build_id` | `Manifest` 中的 `build_id` |

示例：模块 URL 如果是 `https://raw.githubusercontent.com/alice/rules/abcdef/adblock.sgmodule`，作为 `module=` 的值应类似 `https%3A%2F%2Fraw.githubusercontent.com%2Falice%2Frules%2Fabcdef%2Fadblock.sgmodule`。示例的 `abcdef` 只是说明，实际必须使用 API 返回的完整 SHA。

可在 C3 中先 GET 两个 Raw URL 作网络预检，再输出词典；获取内容不等于已经将配置装入 Shadowrocket。

## D. 建立 08:00 个人自动化

1. 快捷指令 → 自动化 → `+` → **特定时间**。
2. 设置 **08:00**，重复 **每天**，选择 **立即运行**；旧版 UI 对应关闭“运行前询问”。
3. 添加 **运行快捷指令** → `SR 获取今天版本`。
4. 从其输出词典读取 `config_scheme`，加 **URL** → **打开 URL**。第一次手动运行时允许打开 Shadowrocket。
5. 在 Shadowrocket 中完成出现的导入/使用确认；检查配置页激活的文件，并点击**使用配置/编译配置**。未出现确认且当前版本直接执行时，仍以配置状态和规则下载日志为准。
6. 回到快捷指令以后，如需同步广告模块，继续下述“广告更新”步骤。

**这里的“每天 08:00”依据手机当前时区。**若手机设在洛杉矶等时区，08:00 当地时间就不是北京时间 08:00。出国/切换时区后需调整触发时间；严格固定北京时间需要按当前时差调整，手机的普通“特定时间”自动化没有本方案可依赖的跨时区准点 SLA。

### 广告更新：保留你的独立开关选择

建议另建 `SR 更新广告模块` 快捷指令：运行 `SR 获取今天版本` → 读取 `module_scheme` → 打开 URL → 在 Shadowrocket 完成模块安装/替换 → 检查模块开关 → 使用/编译配置。**只有你要启用去广告时才运行它。**每天更新时核对是否替换原模块；不同版本可能重新安装或产生重复项，保留一个有效实例，不假定会自动去重或保留关闭状态。

如果你希望在同一 08:00 任务里依次执行两项，可在“打开配置 URL”后添加该系统版本提供的 **等待返回**（Wait to Return）操作，等你从 Shadowrocket 返回，再运行 `SR 更新广告模块`。如果没有这个操作，就分成两个快捷指令手动接续。不要用“等 1 秒/5 秒”代替导入成功回执；这不能证明前一步完成。

如果设备上的 Shadowrocket 在快捷指令操作列表中**实际提供**“更新配置/更新模块”的原生动作，可优先在本机测试后替换导入步骤；必须验证它更新的是规则/模块而非节点订阅，以及锁屏能否运行。本交付未检查你的安装版本，不能把这些动作的存在和后台行为作为既定事实。

**如果你要求两个文件都必须在 08:00 锁屏静默生效，这条要求在已核实接口下无法交付保证。**上述流程能明确触发、选定今天版本并保留人工验收；后台模块/配置每日刷新是额外兜底。

## E. 今天就验证一次

1. 解锁手机，分别手动运行“获取今天版本”“更新分流”“更新广告模块”，处理首次权限提示。
2. 在 Shadowrocket 查看当前主配置的构建编号，模块描述也应来自相同构建。检查“规则集 URL”全部下载成功，再编译。
3. 新开连接测试一项直连、一项代理、一个被广告列表覆盖的域名；查看命中日志。只看文件下载成功不代表编译成功。
4. 将个人自动化临时设为两分钟后，保持解锁测试；再锁屏测试一次。查看锁屏是否需要解锁、是否弹出导入确认，以及模块开关是否被改变。
5. 测试“仓库尚未发布今天版本”时，快捷指令是否停止，旧配置是否继续使用。
6. 验证后恢复每天 08:00；可另外建立 08:10 的失败重试。任何时候不要弹“更新成功”通知，除非已在 Shadowrocket 里确认下载与编译。

## F. 为什么这比单纯等十分钟更可靠

- GitHub：07:50 只是计划触发时间，完整提交成功才是发布完成。
- 网络：完整 SHA 的主文件 + SHA256 命名的子规则固定了文件版本，避免新主配置和旧子规则共享可变 URL。
- iOS：08:00 是尝试触发点，URL 打开、下载、导入、编译是后续步骤，不能把它们等同为一个已完成动作。
- 验收：`manifest.generated_at` 和 `build_id` 可以检查“哪次构建”，Shadowrocket 日志用于检查“手机是否应用”。
